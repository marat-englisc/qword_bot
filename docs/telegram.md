# Telegram: пользовательские сценарии

Фабрика `createTelegramBot(token, db, options?)` находится в `src/telegram/index.ts`.
Её импорт не читает `.env`, не открывает БД и не запускает polling.
Зависимости — существующие репозитории и `createLearningServices`.
`src/config/bot.ts` создаёт экземпляр для приложения; `src/index.ts` регистрирует
список команд в Telegram и запускает его.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Первая настройка либо главное меню для настроенного пользователя |
| `/menu` | Главное меню |
| `/study` | Просроченные повторения, принятые новые карточки, затем рекомендации |
| `/new` | Подбор новых значений с проверкой лимита и нагрузки повторений |
| `/stats` | Число карточек по состояниям, текущие повторения и новые значения за местный день |
| `/settings` | Уровень, дневной лимит, часовой пояс и цель запоминания |
| `/topics` | Интересы и исключённые темы |
| `/help` | Объяснение обучения и четырёх оценок |
| `/cancel` | Завершить текущий ввод и открыть меню |

Все сценарии доступны в личном чате. Команда в группе предлагает перейти
в личный чат, не создавая пользователя. Другие сообщения в группе игнорируются.
Язык интерфейса — русский. Текстовый поиск по словарю и уведомления по расписанию
в этот слой не входят.

## Первая настройка и предпочтения

`/start` → самооценка CEFR → часовой пояс → темы → меню.
Недостающая запись выбранного CEFR создаётся автоматически. Это справочник,
а не автоматическая оценка уровня пользователя.

Часовой пояс выбирается из списка либо вводится как IANA-идентификатор,
например `Asia/Almaty`. Telegram не сообщает надёжный часовой пояс пользователя,
поэтому бот его спрашивает. День, лимит новых слов и даты повторений учитывают
выбранную зону. Дневной лимит в интерфейсе — целое число 0..100, по умолчанию 10;
0 отключает новые рекомендации, сохраняя занятия с уже добавленными карточками.
Цель запоминания выбирается между 85%, 90% и 95%; она меняет интервалы при
следующих ответах, не пересчитывая автоматически все прежние даты.

Темы выводятся страницами по восемь. Нажатие последовательно переключает
нейтральную тему, интерес (`interestWeight=1`), исключение (`isBlocked=true`)
и нейтральное состояние. Изменяются только явные предпочтения; вычисленная
статистика сохраняется. Исключение влияет на новые рекомендации, а не на очередь FSRS.

## Рекомендации и занятия

Предложение показывает отдельное значение, перевод, английское определение,
транскрипцию и до двух примеров. Доступны реакции:

| Кнопка | Результат |
| --- | --- |
| Учить | Атомарное принятие с проверкой дневного лимита; New-карточка и её первый вопрос |
| Уже знаю | Предпочтение `known`, без создания карточки |
| Пропустить на 7 дней | `snoozed` на 7 дней |
| Слишком сложно | `snoozed` на 30 дней |
| Не предлагать | `ignored` |

Перевод уже показан, поэтому «Уже знаю» **не создаёт vocabulary assessment**.
Это исключает использование ответа после подсказки для оценки исходного
словарного знания. Начальный уровень задаётся пользователем; накопленная история
повторений используется существующим сервисом тематических трудностей.
Отдельного диагностического теста исходного словарного запаса пока нет.

Карточка спрашивает значение английского слова и показывает первый английский
пример, если он есть, для контекста. Перевод, определение и подсказка скрыты.
После «Показать ответ» доступны Again/Hard/Good/Easy: «Не помню», «Трудно»,
«Помню», «Легко». Для первого знакомства инструкция предлагает прочитать
значение и оценить лёгкость запоминания. В остальных случаях оценивается
воспоминание до раскрытия ответа. В помощь включено объяснение, что Hard
означает правильный ответ с большим усилием, а не забытое слово.

На кнопках показаны примерные интервалы `fsrs.preview`. Фактическое время
рассчитывается при ответе; оно может отличаться из-за времени на размышление
и fuzz. После сохранения бот показывает дату следующего повторения и кнопку
«Далее». Лимит новых слов не мешает отвечать на уже добавленные карточки.
При отсутствии работы выводятся причина и ближайшее повторение, если оно есть.

## Состояние, повторные нажатия и доставка

Сессия сохраняется в существующей `user_settings` под ключом
`telegram.session.v1`, завершение первой настройки — `telegram.onboarding.v1`.
Новые таблицы и миграции не требуются. Сессия содержит экран, случайный nonce,
ID сообщения и для карточки полный снимок `UserFsrsData`, с которым был задан вопрос.
Даты восстанавливаются при чтении JSON. Повреждённое состояние игнорируется;
пользователь может открыть `/menu`.

Callback содержит только nonce, действие и короткий аргумент; размер ограничен
64 байтами. Обработчик сверяет nonce, личный чат, пользователя и ID сообщения,
а затем допустимость действия для экрана. Идентификаторы значения и рекомендации
берутся из серверной сессии. Оценка до раскрытия ответа не принимается.
Новый экран получает новый nonce, поэтому кнопки из прежних сообщений устаревают.
События одного Telegram-пользователя обрабатываются последовательно внутри
экземпляра бота. Даже после перезапуска сохранённый снимок и проверка версии
карточки в репозитории не позволяют повторно записать один и тот же ответ.

Перед отправкой нового экрана прежняя клавиатура логически инвалидируется
в БД. После успешной доставки сохраняется ID сообщения. `markShown` вызывается
только после подтверждения отправки/редактирования от Telegram; неудачная
доставка не создаёт показ. Если рекомендация стала недоступна, клавиатура
убирается. Сохранение ответа FSRS предшествует отправке подтверждения:
при ошибке доставки ответ остаётся записан, повторное нажатие не дублирует журнал.

Telegram и БД не образуют общую транзакцию. Сбой процесса между доставкой
сообщения и записью её подтверждения может оставить неактивную клавиатуру
или показ без `shownAt`; восстановление доступно через `/study` или `/menu`.
Очередь доставки с гарантией восстановления после такого сбоя не реализована.
Штатный запуск использует один polling-процесс.

Ошибки перехватываются, пользователь получает сообщение о восстановлении.
Стандартный журнал содержит только название ошибки, без URL Bot API, токенов
и текста сообщений. Для собственной диагностики можно передать `onError` в фабрику.
Текст словаря экранируется для HTML, длинные поля обрезаются в пределах лимита
Telegram без разрыва суррогатных пар Unicode.

## Запуск и проверка

Установите зависимости и задайте `.env`:

```dotenv
DB_FILE_NAME=file:local.db
TELEGRAM_API=YOUR_BOT_TOKEN
```

```sh
npm install
npm run db:migrate
npm start
```

В словаре должны быть слова, значения, части речи и уровни CEFR; темы и примеры
необязательны. Пустой словарь не приводит к сбою: бот сообщает, что предложений
нет. Рабочая БД не мигрируется автоматически при старте.
`SIGINT/SIGTERM` останавливают polling; после остановки соединение закрывается.
`npm run build` компилирует приложение в `dist`; скомпилированный запуск —
`node dist/index.js`.

```sh
npm run typecheck
npm run test:telegram
```

Тесты вызывают `bot.handleUpdate` с реальными grammY-обработчиками, сервисами
и репозиториями. Используется libSQL в памяти с настоящими миграциями.
Все методы Bot API перехватываются mock-трансформером; обращений к Telegram
и рабочей БД нет. Проверяются переходы, ограничения, повторные callback,
сохранённые снимки, предпочтения, HTML и ошибки доставки.
