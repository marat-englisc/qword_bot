# Аудит моделей: ограничения, индексы и миграция

Проверены все 16 моделей, включая словарь, справочники, FSRS, настройки и
рекомендательную систему. Рабочая `local.db` только прочитана: прикладные таблицы
на момент аудита пустые, нарушений внешних ключей нет. Изменения схемы проверены
на отдельных базах в памяти с заполненной историей.

## Исправленные ограничения

- `cefr_level.value`: UNIQUE и CHECK на A1/A2/B1/B2/C1/C2. TypeScript enum сам
  по себе не ограничивает данные, записанные напрямую в SQLite.
- `part_of_speech.value`: непустой текст и уникальность по `lower(trim(value))`,
  чтобы `noun`, `NOUN` и ` noun ` не создавали разные строки справочника.
- `word`, `word_meaning`, `word_meaning_example`: обязательные тексты не могут
  состоять только из пробелов, табуляций или переводов строк.
- `topic`: непустое название и slug из строчных a–z, цифр и дефисов, без
  начального/конечного дефиса. Уникальность slug сохранена.
- `word.frequencyRank`: положительное целое; при наличии ранга требуется
  непустой `frequencySource`, чтобы его можно было интерпретировать.
- `user.telegramId`: положительное целое в безопасном диапазоне JavaScript;
  `isAdmin` ограничен 0/1.
- `user_settings`: добавлен обязательный `key`, уникальный в пределах пользователя.
  Значение осталось обычным текстом: здесь допустимы и строки, и сериализованный
  JSON, и пустая строка, если это предусмотрено конкретной настройкой.
- FSRS: состояние 0–3, рейтинг журнала 0–4, неотрицательные целые счётчики и
  интервалы, `lapses <= reps`, корректные timestamps в миллисекундах.
- FSRS память: для New допустимы S=D=0; для Learning/Review/Relearning требуется
  S>0 и 1<=D<=10. Нулевая память первого `ReviewLog` сохранена: журнал хранит
  снимок ДО ответа. Для активной карточки требуется `lastReview`.
- Профили и рекомендации: запрещены дробные лимиты/позиции/количества,
  бесконечные оценки и даты за пределами диапазона JavaScript Date.
- Отложенные значения: `snoozedUntil` должен быть позже создания записи,
  `updatedAt` не может предшествовать `createdAt`.

Общие выражения CHECK находятся в `src/db/schemaChecks.ts`. Проверка
`typeof(column) = 'integer'` нужна: объявление SQLite INTEGER допускает хранение
дробного значения, если оно не преобразуется в целое без потери точности.

Не добавлена уникальность написания `word.title`: одно написание может иметь
разные произношения, например `lead`. Для поиска добавлен обычный индекс.
Отдельные значения одного написания по-прежнему имеют собственные FSRS-карточки.

## Связи

Удаление используемого CEFR или части речи теперь запрещено через RESTRICT.
Раньше CASCADE мог удалить значения, примеры и всю связанную историю обучения.
Удаление самого слова/значения или пользователя сохраняет прежние явные CASCADE.
Удаление CEFR, который используется только в заявленном профиле, по-прежнему
очищает `selfReportedCefrLevelId` через SET NULL.

## Индексы

| Запрос / связь | Индекс |
| --- | --- |
| Поиск написания | `word(title)` |
| Значения слова | `word_meaning(word_id)` |
| Значения по уровню и доступности | `word_meaning(cefr_level_id, is_recommendable)` |
| Значения части речи / её FK | `word_meaning(part_of_speech_id)` |
| Очередь повторений пользователя | `user_fsrs_data(user_id, due)` |
| Уникальность карточки | UNIQUE `user_fsrs_data(user_id, word_meaning_id)` |
| История пользователя по времени | `user_fsrs_review(user_id, review)` |
| История значения пользователя | `user_fsrs_review(user_id, word_meaning_id, review)` |
| История значения / его FK | `user_fsrs_review(word_meaning_id)` |
| Заявленный уровень / его FK | `user_recommendation_profile(self_reported_cefr_level_id)` |
| Настройка пользователя | UNIQUE `user_settings(user_id, key)` |
| Показы пользователя по времени | `word_recommendation(user_id, shown_at)` |

Индекс уровня переставлен с `(is_recommendable, cefr_level_id)` на
`(cefr_level_id, is_recommendable)`: он обслуживает фильтр по обоим полям и поиск
по одному CEFR для проверки FK. Отдельный прежний индекс `user_settings(user_id)`
убран: новый UNIQUE с этим первым столбцом уже покрывает запросы по пользователю.
Остальные составные индексы оставлены там, где порядок столбцов обслуживает
другие фильтры/сортировки.

Тесты проверяют покрытие каждого дочернего FK первым столбцом индекса или PK,
отсутствие одинаковых индексов и `EXPLAIN QUERY PLAN` основных запросов.
Это проверка структуры и выбора плана, а не замер производительности на большой базе.

## Применение миграции

Добавлена миграция `20261010112912_schema_integrity` поверх существующих двух.
Для изменения CHECK/FK требуется пересоздание таблиц. Применяй её стандартным
`migrate(db, { migrationsFolder: "./drizzle" })` из
`drizzle-orm/libsql/migrator`: установленный драйвер вызывает `client.migrate`,
отключает FK ДО начала транзакции и включает после завершения.

[SQLite не позволяет переключать enforcement внешних ключей внутри транзакции](https://www.sqlite.org/foreignkeys.html).
Поэтому миграция содержит начальную проверку, которая отклоняет запуск с
включёнными FK до удаления любой таблицы. Не выполняй её отдельным `executeMultiple`
на обычном соединении или внутри произвольной транзакции с включёнными FK.

Миграция переносит все строки, сохраняет идентификаторы и максимальные значения
`sqlite_sequence`, включая уже удалённые ID. Последняя проверка внешних ключей
отклоняет перенос при обнаружении осиротевших ссылок. Некорректные старые данные
приводят к откату; миграция не удаляет их молча ради новых ограничений.

Старые настройки не имели ключа. Их значения сохраняются под `legacy_<id>`:
например, запись с id=7 получает `key = legacy_7`. По содержимому невозможно
надёжно восстановить назначение произвольной строки. Перед использованием
старых настроек приложением нужно назначить им реальные ключи; для пустой базы
никакого переноса вручную не требуется. Новые записи требуют явного `key`.

Полная проверка IANA-зоны и содержимого произвольного JSON остаётся задачей
сервиса. [Репозитории](repositories.md) нормализуют веса при создании снимка
первичного ответа, проверяют владельца рекомендации и выполняют связанные
изменения в транзакциях. Низкоуровневый CRUD сам по себе не заменяет эти операции.

Проверки: `npm test`, `npm run typecheck`, `npm run typecheck:recommendations`,
`drizzle-kit check`. Общая проверка типов теперь включает исправленные
репозитории и `db/types.ts`. Интеграционные тесты дополнительно сверяют
колонки и первичные ключи всех моделей с применёнными миграциями.
